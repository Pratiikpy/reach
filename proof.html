01 / The problem

The expensive part of AI research is not getting an answer. It is checking one.

A model returns something fluent and mostly right. Somewhere inside are two claims it invented and one it half-remembered from a source that said the opposite. You cannot tell which by reading — that is precisely the failure mode — so you verify it yourself, and the verification costs more than the research saved. Citations were supposed to fix this and mostly have not, because a model can produce a citation the same way it produces everything else: by predicting what one looks like.

04 / Difference

Research with sources you can check.

Three things this does that a similar-sounding service does not.

Citations point at pages it read

The URL fetched during that run, with the full touched-source list alongside the cited subset, so you can see what it read and chose not to use.

It admits when the search missed

<code>relevance</code> and <code>degraded</code> sit in the response envelope, so a calling agent can detect a miss instead of citing irrelevant pages downstream.

Reasoning never reaches you

Models that emit a scratchpad inline, or spend the whole token budget thinking and return nothing, are stripped and retried. You paid for a report, not an inner monologue.

05 / How it works

The mechanism, in order.

What actually happens between your request and the signed answer.

  1. Search — An ordered chain of keyless engines — DuckDuckGo when reachable, then Brave, then Bing. Engines fail differently and unpredictably; depending on one is how a research product silently gets worse.
  2. Score — Every result set is scored against the query's discriminating terms. Below threshold the next engine is tried. If none clears it, the answer returns marked degraded with its relevance score rather than as confident success.
  3. Read — Pages are fetched and reduced to readable text. A fetch that fails is reported as a failure, never dressed up as content.
  4. Write and sign — An agentic loop decides which tools to call and when it has enough, bounded by a deadline that keeps a paid call inside its advertised window. The report is signed over a digest of the whole payload.

How it is built

A Node gateway running OKX's x402 seller SDK proxies to a Python FastAPI engine. Deep research runs off the event loop in a thread pool, so one long run never blocks another caller — measured: the paywall holds about 0.18s while a multi-minute research call is in flight. The model chain spans two API dialects, Anthropic /v1/messages and OpenAI /v1/chat/completions, adapting at the edge so the agentic loop keeps a single internal representation.

06 / Who pays

Why anyone buys this.

Agents that need to know something before they act and cannot afford to be confidently misinformed — a trading agent reading up on a protocol, a support agent answering from live documentation, an AI product that wants real citations without building a crawler. The reason to buy rather than build: the hard part is not the model, it is the engines that rate-limit, the pages that block readers, and the results that quietly go off-topic.
